# 開発ガイドライン：外部対応タスク管理ダッシュボード

このプロジェクトで開発を進める際、一貫して守ってほしいルールをまとめる。

## UI・表示

- UI要素は原則として日本語を使用すること（ボタン、ラベル、メニュー、エラーメッセージ等すべて）
- モバイルファーストで設計し、スマートフォンでの表示・操作を必ず確認すること
- 業務システムとしての情報密度を高めるため、Tailwind CSSの余白は `p-2` `gap-2` を基準とし、無駄な余白を作らないこと
- shadcn/uiのサンプル・テンプレートに含まれる、本プロジェクトと無関係なダミー機能（未接続のボタン、ダミーデータの表など）は流用せず、削除または実際の機能に置き換えること

## データベース・バックエンド

- Supabaseの確認・設定は、可能な場合はMCPツール経由でAIに直接操作させること
- MCPが利用できない場合（利用上限等）は、Supabaseダッシュボードの「SQL Editor」「Table Editor」で代替すること
- テーブルを新規作成する際は、Row Level Security（RLS）を必ず有効化すること
- データの取得・更新は、極力 Server Actions を使用して実装すること（Route Handlerは使用しない）

## 開発の進め方

- 大きな変更を行う前後には、必ず `git add / commit / push` でバックアップを取ること（コミットメッセージは日本語で内容が分かるように書く）
- Phaseごとに開発を進め、各Phase完了時には `docs/progress/` 配下の進捗報告書を更新すること
- 一度に多くの機能を実装せず、Phaseを分割して段階的に進めること
